# LMS handoff pushes the member first; stop logging passwords

- `CrossAppHandoffService` now pushes the customer user to the LMS hub (`TenantUserPusher::upsertToLmsHub`) before asking for a one-time link, like `LmsAccessController`. The LMS only issues links for members it already has, so users not yet synced got `link_request_failed` (LMS 404 "User not found"). A failed push is logged and the link is still requested.
- `CustomerUserController`: removed logging of the entered password and stored hash on `POST /api/user-login`, removed the `debug` field that echoed both in the 401 response, and request-body logs now drop password/token fields (`SECRET_FIELDS`).
- Tests: `CrossAppHandoffTest` (push order, push failure), new `UserLoginSecretsTest`.
