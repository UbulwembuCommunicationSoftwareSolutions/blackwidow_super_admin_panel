# Tenant apps can renew a revoked SSO token

- New `POST /api/v1/sync/users/sso-token` (`customer.bearer`, `UserSyncController::ssoToken`, `UserSyncSsoTokenRequest`). A tenant app that already signed a user in can ask for a fresh hub token when the shared cookie's token was revoked (for example by another app's logout).
- The user is located within the calling subscription's customer, must not be archived or scheduled for deletion, and must have access to the calling app (LMS: `lms_access` or system admin). Issuance and refusals are logged without the token.
- `/go` (and `/lms`) now recover from a missing or revoked cookie token: `CrossAppHandoffService` sends the user once to their CMS `/sso/go?to=…`, which renews the token (or signs them in first) and comes back with `renewed=1`. The CMS is the target app's customer CMS, or the CMS in the `Referer` (needed for the shared LMS). With `renewed=1`, when no CMS is known, or when the target is the CMS itself, the old login fallback applies. Logged as the usual refusal plus `recovery: cms_renew`.
- Tests: `tests/Feature/UserSyncSsoTokenTest.php`, `tests/Feature/CrossAppHandoffTest.php`.
