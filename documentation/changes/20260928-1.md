# Cross-app links go through Super Admin

- New `GET /go?to=<app url>` (`CrossAppHandoffController`, `App\Services\Sso\CrossAppHandoffService`). Reads the shared `external_token` cookie, matches the target host to the user's own customer subscription (or the LMS hub), checks access, and redirects to a one-time sign-in link from the target app (`CMSService::impersonate` for Console/Firearm, `LmsImpersonationService::issueLink` for the LMS). Unknown hosts return 404, so it is not an open redirect.
- Any failure falls back to a plain redirect to the target app (its login page) and logs the reason: `no_cookie`, `token_not_found`, `not_customer_user`, `delete_scheduled`, `no_subscription`, `no_access`, `unsupported_type`, `link_request_failed`, `consume_url_off_host`.
- `GET /lms` now delegates to the same service. On failure it sends the user to the LMS itself instead of `/admin/login?error=unavailable`.
- New `App\Support\Sso\SsoHandoffLog` writes `sso.handoff.redirected` / `sso.handoff.refused` for `/go`, `/lms`, `/customer-portal` and `POST /api/backend/login/sso`. Tokens, codes and consume URLs are never logged.
- Tests: `tests/Feature/CrossAppHandoffTest.php`, `LmsHandoffTest.php`, `CustomerPortalHandoffTest.php`.
