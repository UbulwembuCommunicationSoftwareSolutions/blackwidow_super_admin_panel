# Refresh env variable rows from the real sites

- New `php artisan app:pull-site-envs [ids…] [--type=ID…] [--keys] [--apply]` (`PullSiteEnvsCommand`). For each subscription with a Forge site it reads the site's real `.env` and compares it with the `EnvVariables` rows: keys the site has and Super Admin lacks are added, differing values take the site's, a row is kept when the site's value is empty, and rows the site lacks are left alone. Prints counts (and key names with `--keys`), never values.
- A dry run unless `--apply` is passed. Applying also stores the pulled file on the subscription (`env`), without firing its update hooks. A site that cannot be read is reported and the rest carry on.
- New `App\Support\SiteEnv\SiteEnvReader`: fetches the file from Forge without logging it (`ForgeService::getSiteEnvironment()` writes the whole file, secrets included, to the log) and parses it, unescaping double-quoted values the way `ForgeApi::formatEnvValue()` escapes them.
- Tests: `tests/Feature/PullSiteEnvsCommandTest.php`.
